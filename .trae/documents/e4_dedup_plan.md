## 改动清单（仅 app.py + 一处前端文案）

### 1. Step2 prompt 收紧（`_e4_step2_system`）
- **禁止回显**：输出中不得出现「问题判定」行、任何 [EVAL]/[ORDER]/[NORM]/[REF] 开头的行、
  不得照抄指标数值清单；保留 `#### 问题原文` 锚点标题 + 「判断：」正文。
- 健康/中性问题：标题保留，判断限一句平实结论，**禁止写数值**。
- 有问题/关注问题：可展开；但同一指标在**全文首次出现的问题下**才给数值与完整解释，
  后续问题只写与本问题相关的新角度，用指标名引用、不复述数值。
- 三段式收紧：
  - 显著问题：每条一行（问题 + 直接干预/需询证 + 指标名），不写数值、不复述逐问题段落原话；
  - 可能失真·先观察：不变；
  - 跟进线索与切入点：只写动作（可点名一表人才），不重复数值。
- 保留：评级优先、强弱特质、线索映射等已有硬规则。

### 2. Python 兜底清洗（新增 `_sanitize_e4_step2`，两个路由共用）
在拿到 Step2 content 后、三段截取前执行，防止 AI 不听 prompt：
- 删除行首（允许空白/粗体标记）匹配 `问题判定`、`[EVAL]`、`[ORDER]`、`[NORM]`、`[REF]` 的行；
- 压缩 3+ 连续换行为 2 个；
- 只处理确定性前缀，不做任何语义删改。
- 接入点：one-stop 路由（现 L1652 附近）、prompt-lab step2 路由（现 L2792 附近）。

### 3. Step3 prompt 改为两节（`_e4_step3_system`）
- 输出仅：`### 真实优势`、`### 名单归属`；
- 名单节逐字写规则类别 + 2-3 句数据理由，禁止句尾括号堆叠指标清单、禁止出现其他三类名称；
- 明确禁止输出核心矛盾/下一步（Step2 已承载），禁止复述综合分析草稿原话；
- user 消息措辞「综合分析草稿」相应更新。

### 4. Y4 数据呈现段裁剪（新增 `_strip_y4_data_section`，在 `_assemble_e4_protocol` 内）
- 匹配 `^(#{1,6})\s*.*数据呈现.*$`，删除从该标题到下一个同级或更高级 markdown 标题之间的全部内容
  （保留下一标题及其后内容；Y4 解读的标题/引言行保留）；
- 兜底：再匹配 `**一、数据呈现**` 类粗体行形态；找不到匹配 → 原样返回（安全兜底）；
- 只在拼装下载 md 时生效，不改 DB 存储的 interpretation；prompt-lab 与 one-stop 同走此函数，同时生效。

### 5. 前端文案
- prompt_lab.html L1406「AI 撰写总览（核心矛盾 / 真实优势 / 下一步）」
  →「AI 撰写总览（真实优势 / 名单归属理由）」。
