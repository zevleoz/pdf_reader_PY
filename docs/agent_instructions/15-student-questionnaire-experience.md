# Agent O 指令包：学生端问卷体验重做 —— 防丢答案 · 一题一页 · 高级感

> 需求方原话："给学生发的问卷要做的严谨一点，预防网络问题导致保存失败，然后一页就一个问题，整个问卷要有高级感。"
> 本包重做**学生端作答页**（一次性链接 `/q/<token>` 与账号模式 `/student/q/<id>`）。这是凭远对客户（家长/学生）的直接触点，质量标准按对外产品执行，不按内部工具执行。

## 1. 三个目标（验收即按此）

1. **严谨性（最高优先级）**：任何网络故障、误关闭、刷新、断网，答案都不丢。提交失败必须可恢复、可重试、对用户透明
2. **一题一页**：长页滚动改为向导式逐题作答（46 题的 ERQ+CERQ 也必须轻松完成）
3. **高级感**：纸感 + 盾徽 + serif 的凭远对外品牌面（注意：这与管理端 v2 的冷 SaaS 语汇**不同**——学生端是品牌面，管理端是工具面，两套语汇各归其位）

## 3. 禁止事项

- 不改数据模型：`response_drafts` 结构不动（若做 5.3 的可选项，只允许**新增端点**，不改表结构）
- 不改题库 schema_json 格式、不改 `validate_answers` 的校验规则
- 不改 token/账号/提交的服务端状态机（提交后 token 作废、重复提交拒绝——直接复用）
- 不引入任何前端框架/构建链：Alpine + 原生 JS，移动端优先

## 4. 任务一：防丢答案（严谨性架构）

核心模式：**localStorage 为一级存储，服务端草稿为二级，提交走"确认前可无限重试"**。

- [ ] **即时本机持久化**：每次作答变化立即写 `localStorage`，key = `y4q:{mode}:{assignmentId}:answers`，另存 `:meta`（`{savedAt, submitted:false}`）。写操作同步执行（不是防抖）——localStorage 是同步 API，成本可忽略
- [ ] **云端草稿同步**（账号模式已有 `/student/q/<id>/draft` 端点）：变化后 800ms 防抖上传，失败进入**重发队列**（内存 outbox + 指数退避 1s/2s/5s/15s，页面隐藏时暂停，`visibilitychange` 恢复）
- [ ] **链接模式补云端草稿**（可选项，强烈推荐）：新增 `POST /q/<token>/draft`，token 即凭证（无需 session），写入同一 `response_drafts`（assignment_id 关联，链接模式的 assignment 本来就在）。**零表结构变更**。若执行时不做此项，则链接模式仅本机持久化，并在 UI 上诚实标注"答案保存在本机浏览器"
- [ ] **恢复逻辑**：进入作答页时取两源草稿（本机 meta.savedAt vs 服务端 draft.updated_at），**取较新者**回填；若不同源有冲突，以较新者为准并在顶部细条提示"已恢复你上次的作答（{时间}）"
- [ ] **同步状态指示器**（右上角，常驻小字）：
  - `已保存本机 HH:MM`（默认态，灰）
  - `已同步云端`（账号/链接草稿成功后短暂显示，绿点）
  - `离线 · 将自动重试`（断网或上传失败，黄点 + 旋转小标）
  - 用 `navigator.onLine` + `online`/`offline` 事件驱动
- [ ] **提交流**：
  1. 提交按钮进入 `.is-loading`，禁用
  2. `POST` JSON 提交；**成功**：清 localStorage 该 key → 成功页
  3. **网络错误/5xx**：顶部固定横幅（非 alert）："提交未成功，可能是网络问题。你的答案已保存在本机，不会丢失。" + [重试] 按钮 + 恢复在线后**自动重试一次**（`online` 事件）
  4. **400 校验失败**：按题号跳到第一题出错处，该题卡顶部内联错误（"第 N 题：需要作答"）
  5. **已提交/链接失效响应**（409/400 业务拒绝）：直接展示对应状态页文案，清本机 key
- [ ] **提交幂等**：依赖服务端既有重复提交防护；前端在 busy 期间禁止重复触发；成功页回退按钮不重现表单

## 5. 任务二：一题一页（向导交互）

- [ ] **结构**：服务端把问卷 schema（题目/分区/说明）+ 恢复草稿以 JSON 注入页面（`{{ ... | tojson }}`）；Alpine 组件 `wizard()` 驱动步进。**无 JS 降级**：保留现有的整页表单原生提交路径（`noscript` 提示 + 原有 form action），wizard 只在 JS 可用时接管
- [ ] **步进规则**：
  - 一题一页：题干区 + 选项区 + 底部操作条（左 `上一步` ghost / 右 `下一步` primary）
  - 分区 intro（schema 有 section 时）作为独立的过渡页显示
  - **单选题选中后 250ms 自动前进**（可回退；用户点选即走，是 46 题问卷的关键流畅性）；多选/量表/文本题不自动前进，需点"下一步"
  - "下一步"时当前题必填校验，未答则该题卡抖动提示 + 内联红字
  - 键盘：`Enter` = 下一步（文本域除外）；`1-9` 数字键 = 选对应选项（单选）；`←` = 上一步
- [ ] **进度**：顶部细进度条（红，真实进度=已答数/总题数，**不虚构**）+ `第 N 题 · 共 M 题` 小字
- [ ] **最后一页 = 检查与提交页**：显示已完成 X/M；若有漏答列出题号（点击跳回）；[提交问卷] 主按钮 + "提交后不可修改"提示
- [ ] **过渡动效**：下一题右滑入 / 上一题左滑入，180ms `ease-out`；`prefers-reduced-motion` 全关
- [ ] **焦点管理**：切题后焦点移到题干 heading（`tabindex="-1"`）；进度变化经 `aria-live="polite"` 通报

## 8. 常见坑

- `tojson` 注入 schema 时防 XSS：题干来自 seed（可信源），但仍用 `| tojson` 并在 JS 里用 `x-text` 渲染，禁止 `innerHTML` 拼接题干
- localStorage 在隐私模式可能抛异常——`try/catch` 包裹，失败时静默降级为仅内存 + 云端草稿（并在指示器上只显示云端状态）
- 自动前进 250ms 内用户又点了别的选项：取消前一次前进计时，以最后一次选择为准
- 提交中的"自动重试"只自动一次，失败就交还给用户手动重试（避免无限重试打爆小服务器）
- iOS Safari 的 `beforeunload` 不可靠——不要依赖它做保存，一切靠即时持久化

### 9.3 实测结论（本地 localhost:8002，Flask dev server）

已在浏览器端到端实测通过：

- 46 题 ERQ+CERQ（含 2 个分区 intro 过渡页）：一题一页、单选 250ms 自动前进、`1-9` 数字键选
  选项、`←` 回上一题、未答点「下一步」抖动 + 内联红字、刷新后「已恢复你上次的作答」并落到
  第一道未答题、顶部进度条增长。
- 7 题短问卷（移动端视口）：无横向溢出、选项整行可点、操作条不遮挡；「查看汇总」→ 漏答题号
  芯片可点击跳回；带漏答提交 → 服务端 400 → 自动跳回第一道错题并内联报错；全答后提交 →
  成功面板（盾徽 + serif「提交成功」）；再刷新 → 服务端「问卷已提交」状态页。
- 同步指示器：`已保存本机 HH:MM`（灰）→ 草稿上传成功短暂 `已同步云端`（绿）→ 回落本机；
  **杀服务器后点提交** → 固定横幅「提交未成功，可能是网络问题。你的答案已保存在本机，不会
  丢失。」+「重试」按钮 + 指示器 `离线 · 将自动重试`（黄点旋转）；服务器恢复后点「重试」→
  成功面板。
- 服务端侧（Flask test_client / curl）：链接模式草稿端点 200 且落库；无效 token → 404；已用
  token 重复提交 → 400「该链接已完成作答，不能重复提交」且 responses 只有一条（幂等）；
  账号模式 `/student/q/<id>/draft` **无 `X-CSRF-Token` → 403、带头 → 200**（即 base.html 里
  的 fetch 补丁是必须的，wizard 复用同一补丁）；账号模式全答提交 → 200 + 落库；重复提交被拒。
- 无 JS 降级：原生表单 POST `/q/<token>/submit` 直接返回「提交成功」页（HTTP 200），

### 9.4 其他观察

- `body:has(.q-wrap)` 用于给作答/状态页铺暖纸底：`:has()` 需较新浏览器（Safari 15.4+/Chrome 105+），
